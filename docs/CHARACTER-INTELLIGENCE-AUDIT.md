## 1. تحليل الفيديو المرجعي (الحقيقة المرجعية)

المدة: 72 ثانية، عمودي 720×1280 @30fps، صوت AAC + موسيقى خلفية.

ما يحدث فعليًا في الفيديو:

- الفنان يرسم على وجه شخصية أنمي داخل تطبيق رسم (واجهة تشبه Procreate)، والشخصية **كيان حي داخل اللوحة** يتفاعل مع القلم واليد.
- الشخصية **تتبع القلم بعينيها**، وتُدير رأسها بعيدًا، وتغلق عينيها عند الطلب، وتنتظر، وتتململ.
- **حوار متبادل حقيقي** (نسخة الصوت المستخرجة):
  - «All done. Do you want some cool eyeliner?» / «Sure.» / «All right, close your eyes.» / «Keep them closed.» / «Okay, try not to move.» / «Okay, the other side.» / «Almost done… and voila!» / «Did you draw on my face?» / «No!» / «No, you smudged it.» / «All right, all right, I'll fix it.» / «Oh, what if I did a lightning bolt?» / «Sure.» / «Okay, just give me one minute.» / «Hey, you look sick!» / «Yeah?» / «Yeah!» + ضحك.
- **الصوت بشري 100%**: نبرة عفوية، تنفّس، ضحك، تردد، مقاطعة، جُمَل قصيرة غير مكتملة — وليس صوت مذيع.
- **حركة كاملة الجسد**: الشخصية ترفع يدها وتلمس صدرها/ذقنها، تميل، تنكمش، تعبّس، تبتسم، تحمرّ خدودها.
- **وعي بالأشياء**: الشخصية تعرف أنه تم الرسم على وجهها، تعترض على التلطيخ (smudge)، تعلّق على النتيجة النهائية (البرق الأزرق) — أي أنها **تقرأ محتوى اللوحة نفسه**، لا مجرد إحداثيات لمسة.
- **توقيت** طبيعي: صمت، انتظار أثناء الرسم، ردّ متأخر، مقاطعة، تزامن شفاه دقيق.

خلاصة: الفيديو ليس «أنيميشن جميل»، بل حلقة كاملة
`Perception → Understanding → State → Decision → Emotion → Action → Animation → Voice`
مع **قناة إدراك بصرية** (ما يُرسم) و**قناة صوتية ثنائية الاتجاه** (استماع + كلام).

⚠️ ملاحظة مهنية: هذا الفيديو غالبًا **أنيميشن مرسوم يدويًا إطار بإطار** (لا محرك ذكاء لحظي خلفه). لذلك الهدف ليس «نسخه» تقنيًا بنفس الطريقة، بل **إعادة إنتاج نفس الإحساس** بمحرك حقيقي: rig + إدراك + قرار + صوت طبيعي.

## 2. الحالة الحالية للمشروع (ما هو موجود فعلًا)

### 2.1 معمارية عامة
- TanStack Start + React 19 + Tailwind v4 + shadcn.
- المسارات: `/` (هبوط)، `/characters`، `/scene`، `/about`، `/auth`، `/dashboard`.
- Backend: Server Functions (`touch.functions.ts`, `voice.functions.ts`) + Supabase (جدول `profiles` فقط + auth).
- الذكاء: طلب واحد إلى Lovable AI Gateway (`google/gemini-3-flash-preview`) بـ tool-calling.
- الصوت: ElevenLabs TTS (`eleven_multilingual_v2`).
- الشخصيات: 4 شخصيات معرّفة بصورة JPG ثابتة واحدة لكل شخصية (`src/assets/char-*.jpg`).

### 2.2 نقطة حرجة تشغيلية
`ELEVENLABS_API_KEY` **غير موجود في بيئة هذا المشروع** (`.env` يحوي مفاتيح Supabase فقط).
النتيجة: كل نداء `speakLine` يفشل بـ «ELEVENLABS_API_KEY is not configured» → التجربة الحالية **صامتة فعليًا** حتى قبل الحديث عن جودة الصوت.

## 3. فحص نظام بنظام

لكل نظام: (1) الموجود — (2) الجودة — (3) المشكلة — (4) الناقص — (5) المطلوب تقنيًا.

### 3.1 الذكاء والوعي
1. نداء LLM واحد لكل لمسة، يرجع `mood/animation/expression/speech/voiceTone/affinityDelta/energyDelta/reason`.
2. الجودة: 4/10 — ذكاء «ردّ فعل» وليس وعي.
3. المشكلة: لا يوجد نموذج عالم (World Model). الشخصية لا تعرف أين هي، ما الذي حدث قبل دقيقة، ولا ما يفعله المستخدم الآن. كل لمسة حدث منعزل تقريبًا (تاريخ 6 عناصر فقط، بلا ملخص).
4. الناقص: حلقة إدراك مستمرة، حالة داخلية دائمة، أهداف/نوايا للشخصية، مبادرة ذاتية (تتكلم دون تحفيز).
5. المطلوب: `CharacterCore` بخطوة Tick (10–20Hz محليًا) + LLM «بطيء» كل 1–3 ثوانٍ للتفكير عالي المستوى + طبقة سلوك محلية فورية.

### 3.2 فهم المستخدم والسياق
1. يُرسل: إحداثيات، منطقة تقريبية، نوع اللمسة، المدة، التكرار، الزمن منذ آخر لمسة.
2. الجودة: 3/10.
3. المشكلة: «المنطقة» مستنتجة من إحداثيات على صورة ثابتة (`resolveRegion`) — لا تعرف فعليًا أين الوجه/اليد/الشعر لكل شخصية؛ ولا سياق زمني (جلسة، وقت اليوم، غياب، تكرار عبر الجلسات).
4. الناقص: تمثيل تشريحي حقيقي، نية المستخدم (يداعب؟ يزعج؟ يرسم؟ يختبر؟)، سياق الجلسة.
5. المطلوب: خريطة أجزاء الجسم (mesh/landmarks) لكل شخصية + مُصنِّف نوايا خفيف محليًا + سياق جلسة مُلخَّص.

### 3.3 اتخاذ القرار
1. LLM يختار من 9 أنيميشنات ثابتة.
2. الجودة: 3/10.
3. المشكلة: القرار = اختيار من قائمة صغيرة؛ لا أولويات، لا صراع، لا تجاهل، لا تأجيل، ولا قرار «ألا تفعل شيئًا». وقفل `inflight` يجعل الشخصية **تتجاهل كل لمسة أثناء انشغالها** (فقدان أحداث حقيقي).
4. الناقص: Behavior Tree / Utility AI فوق مخرجات الـLLM، قائمة انتظار أحداث (Event Queue) مع دمج، مقاطعة الفعل الجاري.
5. المطلوب: `DecisionLayer` = Utility scoring (need/urgency/mood/affinity) + LLM للنية طويلة المدى فقط.

### 3.4 الاستماع (Listening)
1. **غير موجود إطلاقًا** — لا `getUserMedia`، لا `MediaRecorder`، لا STT، لا VAD.
2. الجودة: 0/10.
3. المشكلة: التطبيق يوصف بأنه «صوتي» لكنه أحادي الاتجاه (TTS فقط).
4. الناقص: كل شيء: التقاط ميكروفون، كشف نشاط صوتي، تفريغ، barge-in.
5. المطلوب: `MediaRecorder` (webm/m4a) + VAD في المتصفح + STT عبر Gateway (chat completions مع `input_audio`) أو streaming ASR، ثم دمج النص في حلقة القرار.

### 3.5 الصوت ونبرة الحديث
1. ElevenLabs `eleven_multilingual_v2`، إعدادات ثابتة (stability .4 / style .4 / speed 1)، أصوات عامة من المكتبة.
2. الجودة: 2/10 عمليًا (المفتاح مفقود) — و4/10 نظريًا.
3. المشكلة: نبرة «مذيع»: نموذج قديم نسبيًا، جملة كاملة نظيفة، بلا سياق عاطفي، `voiceTone` الذي ينتجه الـLLM **لا يُستخدم أبدًا** عند التوليد. أصوات المكتبة العامة تعطي إحساس Voice-over لا شخصية.
4. الناقص: ربط الانفعال بإعدادات الصوت، نموذج منخفض الكمون، أصوات مخصصة لكل شخصية، تنفّس/ضحك/تردد.
5. المطلوب:
   - `eleven_turbo_v2_5` / `eleven_flash_v2_5` للكمون (<300ms) أو ElevenLabs Realtime/WebSocket streaming.
   - تمرير `voiceTone`/`mood` إلى `voice_settings` ديناميكيًا (stability↓ للانفعال، style↑ للمرح).
   - وسوم أداء داخل النص (`[laughs]`, `[sighs]`, «uh…», «—») بدل جُمَل مصقولة.
   - صوت مخصص/مستنسخ لكل شخصية بدل presets عامة.
   - **ضبط المفتاح ELEVENLABS_API_KEY كخطوة أولى.**

### 3.6 طبيعية الكلام
1. برومبت يفرض «أقل من 18 كلمة، إنجليزية، في الشخصية».
2. الجودة: 3/10.
3. المشكلة: جملة واحدة مصقولة لكل لمسة = إيقاع روبوتي. لا تردد، لا جُمَل ناقصة، لا صمت، لا ردود من كلمة واحدة، لا لغة عربية.
4. الناقص: نموذج حوار (Dialogue Policy) يقرر: أتكلم؟ أصمت؟ أهمهم فقط؟ + دعم اللغة العربية/اللهجة.
5. المطلوب: مخرجات كلام على شكل «أجزاء» (utterance chunks) مع فواصل صمت، ونسبة صمت مقصودة، واختيار لغة حسب لغة المستخدم المكتشفة.

### 3.7 الحركة
1. CSS keyframes: 9 أنيميشنات + breathe + sway على الصورة كاملة.
2. الجودة: 2/10.
3. المشكلة: تحريك **صورة JPG كاملة** (scale/rotate/translate) — لا أطراف، لا رأس مستقل، لا جذع. الحركات منفصلة وتُقطع عند تكرار المفتاح (`animKey`).
4. الناقص: هيكل عظمي (rig) وبلندنغ بين الحركات.
5. المطلوب: تقطيع كل شخصية إلى طبقات (رأس، شعر، عينان، حاجبان، فم، جذع، ذراعان، يدان) عبر Live2D Cubism أو Spine أو rig مخصص بـ PixiJS/Three + skeletal blending، أو VRM/Three للـ3D.

### 3.8 لغة الجسد
1. غير موجودة (لا أذرع ولا وضعيات).
2. الجودة: 0/10.
3. المشكلة: في الفيديو، اليد ترتفع للصدر/الذقن — هذا نصف الإحساس بالحياة.
4. الناقص: مكتبة إيماءات (gesture library) وربطها بالانفعال والكلام.
5. المطلوب: rig بأذرع + طبقة `GestureLayer` تختار إيماءة حسب mood/تركيز/محتوى الكلام، مع IK بسيط لتوجيه اليد نحو نقطة اللمس.

### 3.9 النظر وتتبع المستخدم
1. متغيرات CSS `--look-x/--look-y` تُحسب من موضع المؤشر… لكنها **غير مستخدمة في أي قاعدة CSS فعليًا** (`rig-eyes` يحوي وميضًا فقط).
2. الجودة: 1/10 — «موجود في الكود، لا يعمل بصريًا».
3. المشكلة: العينان جزء من الصورة، لا يمكن تحريكهما فعليًا.
4. الناقص: بؤبؤ منفصل، مدى نظر، رأس يتبع بتأخير، Saccades، نظر بعيد عند التفكير، كسر التواصل البصري عند الخجل.
5. المطلوب: طبقة عين مستقلة (Live2D ParamEyeBallX/Y أو sprite بؤبؤ) + منحنى تتبع (eye→head→torso مع lag) + `GazeController` (targets: مؤشر، قلم، صوت، نقطة تفكير، وجه المستخدم عبر الكاميرا اختياريًا).

### 3.10 الرمش
1. `tk-blink` كل 5.2s ثابت على clipPath من نفس الصورة.
2. الجودة: 2/10.
3. المشكلة: إيقاع ميكانيكي منتظم، لا يتأثر بالحالة، وclip بصري تقريبي (قد يظهر كخلل).
4. الناقص: عشوائية طبيعية (توزيع 2–8s)، رمش مزدوج، رمش عند بداية الكلام/المفاجأة، إغلاق طويل عند الراحة أو عند طلب «أغمض عينيك» (كما في الفيديو).
5. المطلوب: `BlinkController` مدفوع بالحالة + أصول عين مغلقة حقيقية.

### 3.11 تعبيرات الوجه
1. `expression` نص يرجع من الـLLM — **لا يُعرض ولا يؤثر على أي شيء**.
2. الجودة: 1/10.
3. المشكلة: لا يوجد نظام وجه أصلًا؛ الوجه صورة مطبوعة.
4. الناقص: حاجبان، فم، جفون، خدود (blush)، عرق، دموع، رموز أنمي.
5. المطلوب: FACS مبسّط (8–12 معامل: browUp/Down/Angry, eyeOpen, mouthOpen/Smile/Frown, blush, tear…) + خريطة انفعال→معاملات + interpolation ناعم بين التعبيرات.

### 3.12 التفكير والتردد
1. مؤشر Loader صغير فقط أثناء انتظار الـLLM.
2. الجودة: 1/10.
3. المشكلة: زمن الانتظار يظهر كـ«تحميل» لا كتفكير شخصية؛ لا صوت تفكير، لا نظر جانبي.
4. الناقص: سلوك ملء الفراغ (filler behavior): «همم…»، نظرة لأعلى، إمالة رأس، توقف قبل الرد.
5. المطلوب: طبقة Latency Masking تبدأ فورًا عند الحدث بينما يعمل الـLLM في الخلفية (استجابة محلية <100ms ثم استبدالها بالقرار الذكي).

### 3.13 الجلوس والوقوف / وضعيات الجسد
1. غير موجود — لقطة صدرية ثابتة.
2. الجودة: 0/10.
3. الناقص: أوضاع متعددة (جلوس، وقوف، اتكاء، إدارة الظهر) وانتقالات بينها.
4. المطلوب: مجموعة Poses في الـrig + `PostureController` مرتبط بالطاقة والمزاج ومدة الجلسة.

### 3.14 التفاعل باللمس والرسم
1. لمس: `useCharacterTouch` جيد نسبيًا (tap/double/long-press/hold/drag/swipe + burst + travel).
2. الجودة: لمس 6/10 — **رسم 0/10 (غير موجود)**.
3. المشكلة: لا يوجد Canvas ولا فرشاة ولا طبقات ولا حفظ لما رُسم. أهم سلوك في الفيديو (الرسم على الوجه والتعليق عليه) غير مُنفَّذ.
4. الناقص: canvas رسم فوق الشخصية، ربط الضربة بالمنطقة التشريحية، ذاكرة بصرية لما رُسم، ردّ فعل الشخصية أثناء الرسم وبعده.
5. المطلوب: طبقة رسم (`<canvas>`/PixiJS) + Stroke Analyzer (منطقة، طول، لون، شكل تقريبي) + تمرير لقطة منخفضة الدقة للنموذج متعدد الوسائط ليعلّق على النتيجة فعلًا.

### 3.15 فهم ما يحدث حول الشخصية
1. غير موجود.
2. الجودة: 0/10.
3. الناقص: وعي بالوقت، بغياب المستخدم، بالضجيج، بتغيّر الشخصية المختارة، بالكاميرا (اختياري).
4. المطلوب: `EnvironmentSensors` (idle timer, tab visibility, وقت اليوم, مستوى صوت الميك, اختياريًا face-detection عبر MediaPipe).

### 3.16 معرفة الأشياء والتفاعل معها
1. غير موجود (لا أدوات، لا أغراض، لا فرشاة معروفة للشخصية).
2. الجودة: 0/10.
3. المطلوب: Object Registry (قلم، فرشاة، لون، مرآة…) مع Affordances، وتمريرها ضمن حالة الإدراك.

### 3.17 توقيت الكلام والحركة
1. الحركة تبدأ محليًا فورًا، ثم الكلام يصل بعد نداءين متسلسلين (LLM ثم TTS).
2. الجودة: 2/10.
3. المشكلة: تأخير تراكمي (تقدير 1.5–4s)، والحركة تنتهي قبل أن يبدأ الصوت → انفصال تام بين الجسد والصوت.
4. الناقص: جدولة زمنية موحّدة (Timeline/Beat scheduler).
5. المطلوب: بث LLM (stream) → بدء TTS على أول جملة → جدولة الأنيميشن على مؤشرات زمنية للصوت (onset/emphasis) بدل تشغيلها مسبقًا.

### 3.18 الذاكرة
1. `useState` في المكوّن فقط: 12 دورًا + affinity/energy، وتُمحى عند إعادة التحميل أو تغيير الشخصية (`key={character.id}`).
2. الجودة: 1/10.
3. الناقص: ذاكرة دائمة (قصيرة/طويلة/دلالية)، معرفة اسم المستخدم وتفضيلاته، أحداث بارزة («رسمت لي برقًا أزرق»).
4. المطلوب: جداول `sessions`, `interactions`, `memories` (+ pgvector للاسترجاع الدلالي) مع RLS و GRANTs، وتلخيص دوري (memory consolidation).

### 3.19 المقاطعة (Barge-in)
1. غير موجودة؛ بل يوجد قفل يمنع أي حدث جديد أثناء المعالجة.
2. الجودة: 0/10.
3. المطلوب: إلغاء قابل للمقاطعة على كل المستويات — `AbortController` لطلبات LLM/TTS، fade-out للصوت الجاري، مقاطعة الأنيميشن بـblending، وسياسة «متى يحق للمستخدم أن يقاطع».

### 3.20 المشاعر
1. `mood` مُصنَّف + `affinity`/`energy` مع clamp، تتحدث فقط عند اللمس.
2. الجودة: 3/10.
3. المشكلة: قفزات فورية بين المزاجات بلا انتقال، ولا اضمحلال زمني (decay)، ولا مستويات (شدة الانفعال).
4. المطلوب: نموذج انفعال مستمر (valence/arousal/dominance) + decay نحو خط أساس + شخصية (personality) تعدّل الاستجابة + تحويله إلى تعبير وصوت وحركة معًا.

### 3.21 Lip Sync
1. `rig-mouth-talk`: أنيميشن فم متكرر كل 0.32s أثناء تشغيل الصوت (clip من نفس الصورة).
2. الجودة: 1/10 — «فم يتحرك» لا مزامنة.
3. الناقص: viseme حقيقي مرتبط بالصوت.
4. المطلوب: تحليل صوتي لحظي عبر `WebAudio AnalyserNode` (RMS/formants) كحد أدنى، أو أفضل: أشكال فم A/I/U/E/O + مطابقة من phoneme timings (Rhubarb أو timestamps من ElevenLabs) مع أصول فم منفصلة.

### 3.22 الانتقال بين الحالات
1. `setAnimation` + `animKey` يعيد تشغيل الأنيميشن من الصفر.
2. الجودة: 2/10.
3. المشكلة: قطع حاد بين الحركات، لا cross-fade، لا أولوية بين طبقات (idle vs reaction vs speech).
4. المطلوب: State Machine طبقية (Base/Locomotion → Emotion → Gesture → Speech → Look) مع أوزان وblending، مثل نظام Animator Layers.

### 3.23 الإحساس بأنها كيان حي مستقل
1. لا مبادرة، لا سلوك تلقائي، لا حياة أثناء السكون سوى تنفّس CSS.
2. الجودة: 2/10.
3. المطلوب: Autonomy Loop — micro-motions مستمرة عشوائية، ملل، فضول، مبادرة بالكلام بعد صمت، ردّ فعل على عودة المستخدم، أهداف صغيرة.

## 4. الأسباب الجذرية لضعف التجربة

1. **الأصول ثابتة**: صورة JPG واحدة لكل شخصية → سقف صلب لأي حركة/تعبير/نظر/lip-sync. هذا هو العائق #1؛ لا يمكن حلّه ببرمجة.
2. **معمارية Trigger→Response**: حدث واحد ← نداء واحد ← رد واحد. لا حلقة زمنية مستمرة، لا حالة دائمة.
3. **قناة إدراك واحدة (اللمس فقط)**: لا سمع، لا رؤية، لا رسم، لا بيئة.
4. **كمون تسلسلي غير مُقنَّع**: LLM ثم TTS بالتتابع، بلا streaming، بلا سلوك ملء فراغ.
5. **الصوت غير مرتبط بالحالة** + مفتاح ElevenLabs مفقود + نموذج/إعدادات ثابتة.
6. **لا ذاكرة دائمة**: كل جلسة تبدأ من الصفر، فتنهار الألفة.
7. **قفل يتجاهل الأحداث** بدل قائمة انتظار ومقاطعة.

## 6. المعمارية المستهدفة

```
        ┌──────────────── Perception ────────────────┐
        │ touch/pointer · draw strokes · mic(VAD+STT)│
        │ idle/visibility/time · (camera: face/gaze) │
        └───────────────┬────────────────────────────┘
                        ▼
                 Understanding (fast local classifier + slow LLM)
                        ▼
     ┌──────────── Character State (persistent) ─────────────┐
     │ mood(V/A/D) · energy · affinity · attention · goals    │
     │ memory: short / episodic / semantic(pgvector)          │
     └───────────────┬────────────────────────────────────────┘
                     ▼
              Decision (Utility/Behavior Tree + LLM intent)
                     ▼
                  Emotion mapping
                     ▼
        Action Plan  →  { speech chunks, gesture, gaze, expression, posture }
                     ▼
   ┌──────── Animation Layers ────────┐   ┌──────── Voice ────────┐
   │ Base/Breath · Posture · Emotion  │   │ streaming TTS         │
   │ Gesture · Gaze · Blink · Viseme  │◄──┤ visemes + timings     │
   └──────────────────────────────────┘   └───────────────────────┘
                     ▲
              Tick loop @ 60fps (render) / 15Hz (brain-fast) / 0.5–1Hz (brain-slow)
```

قواعد ثابتة:
- **استجابة محلية خلال <100ms** دائمًا (نظر + رمش + micro-move)، والذكاء يصل لاحقًا ويُدمج.
- **كل شيء قابل للمقاطعة** (AbortController + fade + blending).
- **لا Triggers نصية ثابتة**: القرار من الحالة والسياق.

## 7. خطة التنفيذ المرحلية

### المرحلة 0 — تمكين وأساسيات (0.5–1 يوم)
- ربط/إضافة `ELEVENLABS_API_KEY` والتحقق من التوليد فعليًا.
- إزالة قفل `inflight` واستبداله بـEvent Queue + AbortController.
- استخدام `voiceTone`/`mood` في `voice_settings`، والتحويل إلى `eleven_turbo_v2_5` أو `flash_v2_5`.
- **معيار القبول**: صوت يعمل، كمون كلام أول < 1.2s، لا لمسة تُهمَل.

### المرحلة 1 — Character Core + الحياة الدقيقة (2–4 أيام)
- `CharacterCore`: حلقة tick، حالة مستمرة (V/A/D + energy + attention + decay)، Event Queue.
- `GazeController` + `BlinkController` + micro-motions (يعملان محليًا بلا LLM).
- تفعيل `--look-x/--look-y` فعليًا (حاليًا محسوبة وغير مستخدمة).
- **معيار القبول**: الشخصية تبدو حية وهي ساكنة تمامًا، وتتبع المؤشر بعينيها ورأسها بتأخير طبيعي.

### المرحلة 2 — Rig حقيقي (5–10 أيام) ← أعلى قيمة بصرية
- اختيار المسار: **Live2D Cubism** (الأنسب للأنمي 2D) أو Spine أو rig مخصص PixiJS.
- إعادة إنتاج الشخصيات كطبقات: شعر/رأس/عين يمنى/يسرى/بؤبؤ/حاجبان/فم/خدود/جذع/ذراعان.
- طبقات أنيميشن مع blending وأولويات + انتقالات ناعمة (بديل `animKey`).
- **معيار القبول**: إدارة رأس، نظر مستقل، 8+ تعبيرات، انتقال ناعم بلا قطع.

### المرحلة 3 — الصوت البشري و Lip Sync (3–5 أيام)
- بث TTS (WebSocket/streaming) + تقسيم الكلام إلى chunks.
- Viseme من `AnalyserNode` كبداية، ثم phoneme timings لدقة أعلى.
- وسوم أداء (تنفّس، ضحك، تردد) + إعدادات صوت مرتبطة بالانفعال + صوت مخصص لكل شخصية.
- دعم العربية (اكتشاف لغة المستخدم واختيار الصوت/النموذج).
- **معيار القبول**: مستمع لا يصف الصوت بأنه «مذيع»، والفم يطابق الصوت ضمن ~80ms.

### المرحلة 4 — الاستماع والمقاطعة (3–5 أيام)
- ميكروفون + VAD + STT (Gateway `input_audio` أو ASR بثّي).
- Turn-taking: من يتكلم الآن، barge-in، backchannel («مم-هم») أثناء استماع المستخدم.
- **معيار القبول**: يمكن مقاطعة الشخصية بالكلام، فتصمت خلال <300ms وتردّ في السياق.

### المرحلة 5 — الذاكرة والاستقلالية (3–5 أيام)
- جداول `sessions`/`interactions`/`memories` + pgvector + RLS + GRANTs.
- استرجاع ذاكرة قبل كل قرار + تلخيص دوري.
- Autonomy: ملل، مبادرة، ترحيب بالعودة، تعليق تلقائي.
- **معيار القبول**: الشخصية تتذكر حدثًا من جلسة سابقة وتشير إليه دون طلب.

### المرحلة 6 — الرسم والوعي البصري (5–8 أيام) ← مشهد الفيديو نفسه
- طبقة Canvas رسم فوق الـrig + فرشاة/ألوان/طبقات + محو.
- Stroke Analyzer (منطقة تشريحية، لون، طول، شكل) + ردّ فعل لحظي أثناء الرسم (تململ، «لا تتحرك»، إغلاق عين عند الرسم قرب العين).
- بعد الانتهاء: إرسال لقطة مصغّرة إلى نموذج متعدد الوسائط ليعلّق على النتيجة فعلًا.
- **معيار القبول**: يمكن إعادة إنتاج تسلسل الفيديو (eyeliner → smudge → lightning bolt → تعليق) بشكل ناشئ لا مبرمج.

### المرحلة 7 — التلميع (مستمر)
- وعي بيئي، أدوات/أشياء، وضعيات جلوس/وقوف، تحسينات إيقاع وتوقيت، قياس جودة (latency budget, "aliveness" checklist).

## 9. ما يجب عدم فعله
- إضافة أنيميشنات CSS جديدة على الصورة الثابتة (لن يرفع السقف).
- ربط سلوكيات بكلمات مفتاحية أو triggers ثابتة.
- إبقاء TTS غير بثّي مع نداءات متسلسلة.
- بناء ذاكرة في `useState` فقط.

## 10. ملخص تنفيذي بجملة واحدة
المشروع اليوم = **صورة ثابتة + نداء LLM لكل لمسة + TTS معطّل**، بينما الفيديو = **كيان مرسوم برِيغ كامل، بحواس متعددة، وحوار بشري بتوقيت طبيعي**؛ والطريق للوصول هو: تفعيل الصوت فورًا، ثم Character Core مستمر، ثم rig حقيقي، ثم صوت بثّي مع lip-sync، ثم استماع ومقاطعة، ثم ذاكرة واستقلالية، وأخيرًا الرسم والوعي البصري.
